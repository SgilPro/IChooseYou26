1. 資料處理與分析線：我需要你針對寶可夢雙打頻道做影片分析 (第一個分析對象會是 Fiske Pokemon)，流程大概如下
   1. 先掃整個頻道 (https://www.youtube.com/@fiskepokemon) 把資料輸入一張主表 (你現在要怎麼存，csv 或 json 等格式都可以，之後如果我們有正式的資料庫再嚴格遵守就行)，影片頻道欄位填寫這個 youtube channel，author 的話如果你從 description 或者逐字稿或者影片有抓到再填。
   2. 逐一影片去分析包含但不限於以下欄位 (可參考我的 notion db https://app.notion.com/p/jake-the-dog/24a796b1ebe180f686d2d145ed70a25a?v=24a796b1ebe180c5b49a000c66117085&source=copy_link)：name, regulation set (foreign key/notion relation 的概念，regulation set 的詳細資訊包含它屬於哪個遊戲，像是 Champions, Scarlet & Violet, etc. 還有限制類型像是雙神、單神、幻獸、二級神、無神獸，以及機制像是太晶化、Mega、極巨化等), tags (隊伍組成的相關戰術概念，像是天氣、控速手段、強化手段), video url, author, team members (六隻寶可夢〈也會是 foreign key/notion relation，寶可夢資訊又會有 foreign key 連到寶可夢圖鑑的編號，以及這個寶可夢實體，有點像是 class vs. instance，然後 instance 這邊我們要記錄努力值/能力值分布、性格、特性選擇、攜帶道具、技能 set)
   3. 第二步驟會先透過影片資訊抓取一些 primary fields，第三步（可以是未來進階再做）則會是去分析這個隊伍的 tag 填上去（第二步也會填 tag 但比較是基於既有資訊，像是隊伍名稱就提到順風空間隊、高速指導隊、平衡隊、受隊之類的）
   4. 有個需要補充的點是我們這個流程第一個實驗對象是 Fiske Pokemon，但他有很多影片是會員影片你可能無法 access，不過不用擔心，大部分會員影片都是公開影片的延伸，會是同一支隊伍。如果有一些會員影片才有的隊伍，也可以就公開資訊先記錄，然後多一個 field 去紀錄這是會員影片，我們之後可以用我有會員的帳號去登入去 access，再來補資訊即可。
