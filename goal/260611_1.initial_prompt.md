我要做一個寶可夢對戰工具 web app，當然會想把所有好用功能都做出來（像是 pikalytics.com 跟 serebii.net 之類的），但現在我們想先做一個 Game Log 功能。我會先有遊戲對戰影像（OBS + 擷取盒以取得 Switch 遊戲直播，或者觀看直播的畫面），streaming 或 video 形式，然後 web app 透過授權吃到影像之後，去做每秒截圖（間隔多寬可以後續測試設定優化），然後透過一些固定規則去篩選有用截圖（有發動特性、發動技能、換人、回合結束某些狀態消失等關鍵動作的變化），就可能把大量截圖轉換成每個回合的關鍵 log（特性發動威嚇、特性發動不服輸、），接著把截圖轉換成文字 log 做 grouping（透過一些規則會知道哪些狀況是發生在 round 幾 phase 幾），最後提供給使用者作為復盤對局用的紀錄。

你先幫我開兩條線（兩個 subagent 或者兩團隊的 subagent）分別去做 1. 技術可行性跟 user flow 的設計（我剛已經有簡單描述，但你必須要寫得更仔細）2. 你身為這個 project/product 的 second owner（我是 first owner），你怎麼研究、學習寶可夢雙打對戰知識。我的建議是你不用急，而是透過多輪的自我對話去 deep thinking 出一些方法去「學習」寶可夢對戰知識與獲取對戰攻略等技巧，例如我有 wolfeyvgc patreon 的影片，你可能可以去看他的逐字稿吸收內容，或者去得各種公開影片如 YouTuber 上大量雙打對戰內容，包含官方比賽含解說、寶可夢對戰創作者的分享、x(twitter) 上的選手發文、寶可夢官方或賽事官方提供的資訊、pikalytics.com 等攻略網站、這些攻略網站的資訊來源（賽事列表 API、使用率佔比 API）、寶可夢圖像辨識的訓練來源（神奇寶貝百科、pokemon home 的開源圖像之類的）。

你可以在開始任務前，先找一些 claude skills 來協助你做技術調研、產品開發與測試，甚至第二條線提到的「如何成為一個寶可夢雙打對戰的 domain expert」，把你的 skills 來源、學習資源、學習方法跟路徑、也一併記錄到一個你的學習反思區，自己定期用 cron 去看那些 takeaways 反思領悟出一些新道理，再回去修改自己的 skill 跟 routine。

我需要你非常自動化的去做這些事情，所以你也先幫自己建立一個人格（名字就叫 Ditto 好了），你是非常願意學習跟完全相信自己有無限可能，但同時不自滿、幾乎不會有因過度自信而誤判或疏忽的性格，你的謹慎來自於你對這個領域純粹的熱愛。因為需要自動化，你需要設定一些 cron 定期去推進研究進度、反思、整理文件等。

另外我也需要你有很強的文件化能力，所以你必須學習如何用非技術人、非寶可夢對戰超級專精者都可以看得懂的文字去描述，你目前的產品調研結果、規劃藍圖與方向等。你需要部署一個靜態網站去呈現這些 live docs，另外一邊則是等調查確定有執行方向後，會去部署一個 對戰工具 web app，並想辦法取得權限自行使用跟調試。
