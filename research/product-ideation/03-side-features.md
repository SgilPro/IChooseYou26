# 旁支功能構思（side features）

> 構思階段 · 2026-06-14 · 把第一擁有者提到的「使用者登入/儲存 Log、auth、選出畫面分析」當鷹架，往外延伸更多方向。每項標 **價值 / 成本 / 依賴 / 現在做不做**。

## A. 儲存自己的 Log（先做、低成本）
- **做什麼**：把分析完的 GameLog 存起來，下次打開還在；可命名、列表、刪除、重新開啟編輯。
- **為什麼**：目前重整頁面成果就消失，復盤工具卻最需要「累積」。這是把一次性工具變成「我的對戰庫」的第一步。
- **成本**：低。純前端用 **IndexedDB** 存（影片不存、只存事件 JSON + 縮圖）。
- **依賴**：無（不需後端、不需登入）。
- **現在做不做**：**建議做**——它讓其他功能（個人弱點報告、對手 scouting）有資料基礎。

## B. ROI 設定的持久化與設定檔（先做、低成本）
- **做什麼**：把使用者抓好的多塊 ROI 存成具名 preset（如「SV 1080p」「Champions 直播版」），可切換、匯出/匯入 JSON。
- **為什麼**：第一擁有者回饋「ROI 要練習抓」。抓好一次就不該再抓第二次；不同畫面來源各存一套。
- **成本**：低。localStorage（presets 小）或 IndexedDB；匯出/匯入用 JSON blob。
- **依賴**：無。
- **現在做不做**：**建議做**，與 A 一起，CP 值最高。

## C. 選出（Team Preview）畫面分析（中成本、高價值）
- **做什麼**：獨立的「選出畫面」擷取流程——辨識雙方 6 隻、記錄我方帶哪 4、先發 pair；對手帶的隨對戰揭露。
- **為什麼**：雙打勝負常在選出就埋下。這是 GameLog 缺的一塊核心拼圖（見 `01-gamelog-data-model.md`），第一擁有者也點名了。
- **成本**：中。選出畫面是**靜態、圖示固定**，比動態訊息框好辨識；但需要寶可夢圖示辨識（非 OCR），可接 sprite 比對（PokeAPI/HOME 圖庫，見領域線 03 號文件）。
- **依賴**：圖示辨識資料集；可先做「人工框選 + 手動標註」半自動版。
- **現在做不做**：**建議排入近期**，先做半自動（使用者圈出 6 隻、工具裁切、之後再加自動辨識）。

## D. 帳號 / 登入 / 雲端同步（中後期）
- **做什麼**：登入後 Log 存雲端、跨裝置同步、可分享。
- **為什麼**：跨裝置、備份、未來社群功能的前提。
- **成本**：中（要後端 + auth + DB）。輕量解：**Supabase / Firebase**（內建 auth + DB + row-level security），或自架。
- **依賴**：後端基礎建設。
- **現在做不做**：**先不做**。先用 A（IndexedDB 本機儲存）滿足 80% 需求；等有跨裝置/分享的真實需求再上雲。先本機、後雲端，避免過早綁定後端。

## E. 復盤分享連結（中後期）
- **做什麼**：把一場 GameLog 產生唯讀分享連結，貼給隊友/教練看。
- **為什麼**：VGC 玩家常找人 review；分享是天然傳播。
- **成本**：中（需雲端儲存 Log）。
- **依賴**：D 或至少一個存 Log 的後端。
- **現在做不做**：先不做，與 D 綁。可先用「匯出 JSON / 匯出 Markdown 戰報」當低成本替代。

## F. 戰報匯出格式升級（低成本、快速加值）
- **做什麼**：除了現有 JSON，加「**人類可讀的 Markdown 戰報**」與「逐回合摘要卡」匯出。
- **為什麼**：JSON 給機器，Markdown 給人——玩家想直接貼到 Discord/筆記復盤。
- **成本**：低（從事件流產生文字）。
- **現在做不做**：**可順手做**，與藍圖 Phase 1 的「單場自動摘要」呼應。

## G. 對手 scouting / 個人弱點報告（遠期，依賴資料累積）
- 見 `research/line3-competitor-tools/02-feature-matrix-and-roadmap.md` 的 Phase 3。前提是 A（Log 累積）先到位。**現在不做**，但 A 的資料模型要先為它留空間。

---

## 小結：旁支功能的優先序

| 優先 | 功能 | 成本 | 為什麼先做 |
|---|---|---|---|
| 1 | A 本機儲存 Log（IndexedDB） | 低 | 把一次性工具變成對戰庫，是其他功能的地基 |
| 1 | B ROI preset 持久化 + 匯出入 | 低 | 直接解決「ROI 要重抓」的痛點 |
| 2 | F Markdown 戰報匯出 | 低 | 快速加值、貼得出去 |
| 2 | C 選出畫面（半自動） | 中 | 雙打核心拼圖、價值高 |
| 後 | D 登入/雲端、E 分享、G scouting | 中–高 | 等本機版驗證 + 真實跨裝置/社群需求 |

> 原則：**先本機、後雲端；先半自動、後自動**。不為了「看起來完整」過早引入 auth/後端複雜度。
