## 白話版：RAG 是什麼、我們要做什麼

RAG（檢索增強生成）＝「先從自家資料裡找出相關段落，再讓 Claude 看著這些段落回答」。目的是讓 Ditto（之後是網站）回答雙打問題時**有憑有據**：引用 Fiske Pokémon 的影片字幕與隊伍、`research/` 文件、公開賽事／使用率資料、以及第一擁有者的 Notion 筆記，並能說「這段出自哪支影片第幾分鐘」。

## 我查到的關鍵數字（皆為倉庫實測或附來源）

- 頻道共 **679 支影片、約 798 小時**（有時長者 652 支，平均 73 分鐘；`channel-index.json`）。以播放清單歸類，**對戰相關 377 支（56%）、467 小時（59%）**；另有 163 支不在任何清單，實際比例介於 56–80%。（原稿「約 70%」沒有依據。）
- Fiske 影片有**人工上傳的 zh-TW 字幕**（不是自動聽寫；已抓的 36 支全部有）。36 支實測密度**每分鐘 199–360 字，中位 259**。推算全頻道 **約 10–17M 字 ≈ 12–20M tokens**（中位估 15M）；對戰子集約 9–12M tokens。
- 把它全部做成向量，用最便宜的 API（OpenAI text-embedding-3-small 或 Voyage voyage-4-lite，皆 $0.02/M tokens）**不到 1 美元**（≈ $0.3；Voyage 有 2 億 token 免費額度，等於 $0）；本機開源 bge-m3 則是 0 元。**embedding 不是成本問題。**
- `research/` 全部文件約 **17.6 萬字元（中文約 4.5 萬字），估 8–10 萬 tokens**——比原稿寫的「1.4 萬字」多四倍，但仍能整包放進 Claude 的 1M 上下文；只是整包餵一次在 Opus 5.5 約 $0.35–0.40，不是免費。
- 單支影片字幕約 2 萬字 ≈ **2–3 萬 tokens**；只要先把候選影片篩到 3–5 支，就能整段放進上下文回答，一問約 $0.25–0.6（Opus 5.5）。
- **但「篩選」今天還篩不了**：字幕只抓了 36／679 支、章節標記只有 7 支、規則組只有 14 支、隊伍 JSON 0 筆。這些是 line 4（影片資料線）的工作，RAG 線的第一步要等它。

## 我的建議（五行）

1. **先不做向量。** 第一階段用「結構化篩選（隊伍 JSON／SQL）→ 關鍵字全文檢索（SQLite FTS5）→ 命中影片的章節字幕整段餵 Claude」的無向量基線，搭配評估集量化命中率；向量索引只在基線不及格、且確認不是「欄位沒填／別名沒擴」造成時才加。基線的已知弱點：兩字詞（守住、順風、威嚇）在 FTS5 trigram 查不到、口語改寫與「戰術概念型」問題會漏——詳見 `01-pre-plan.md` 第六節。
2. **語料分層處理。** 隊伍／規則組／使用率是結構化資料，一律走 SQL／filter；字幕按「章節 → 60–90 秒窗」切塊並在每塊前綴影片名、規則組、章節、時間戳（Anthropic「contextual retrieval」做法）；研究文件按標題切。
3. **架構先選 (C) 本機單檔 SQLite**（FTS5 + sqlite-vec），與現有 `data/` JSON 同倉庫、可版控、Ditto 每日 routine 增量更新；網站需要時再同步到 (B) Supabase pgvector（免費方案每專案 500 MB、一週沒動會暫停）。
4. **embedding 模型先用開源 bge-m3**（MIT、8192 tokens、同時出 dense+sparse 向量、多語），API 候選是 voyage-4-lite／text-embedding-3-small；繁中沒有公開的專屬基準，**必須用我們自己的評估集實測後再定案**。
5. **合規紅線：** YouTube 條款禁止未經許可的自動化存取與重製；字幕只供本機研究與摘要，**網站不得重發布字幕全文**，只能給引述、時間戳與原影片連結；會員影片不繞過。把剩下 643 支字幕抓齊的節奏，需要第一擁有者決定。

## 里程碑與 go/no-go

M0（本文，不實作）→ **M1 前置**（line 4 補齊字幕／章節／隊伍 JSON／別名表；否則 M1 的數字沒意義）→ M1（評估集擴到 40–50 題 + 無向量基線，約 1 週、幾乎 0 元）→ 可測題命中率@3 < 80% 才進 M2（本機混合索引）→ 命中率@5 ≥ 85% 且忠實度 ≥ 0.9 才進 M3（Supabase 同步 + Notion）→ M4 網站問答。詳見 `01-pre-plan.md` 第十一節。

## 名詞小抄（給非工程師）

- **embedding／向量**：把一段文字變成一串數字，意思相近的文字數字也相近，用來「找意思像的段落」。
- **FTS5／BM25／關鍵字檢索**：傳統全文搜尋，找「字面上出現」的段落；快、免費、但不懂同義詞。
- **trigram**：把中文每三個連續字當一個索引單位，解決中文沒有空格的問題；代價是兩個字的詞查不到。
- **sqlite-vec／pgvector**：分別是 SQLite 與 Postgres 裡存向量、做向量搜尋的外掛。
- **命中率@3（Hit@3）**：檢索前三名裡有沒有包含正確答案所在的段落；**忠實度（Faithfulness）**：回答的每句話是否都能對回檢索到的原文。
- **contextual retrieval**：切塊時在每塊前面加一句「這段出自哪支影片哪個章節」，讓檢索更準（Anthropic 2024 年的做法）。
