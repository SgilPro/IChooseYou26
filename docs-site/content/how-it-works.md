# 運作原理（白話版）

這頁用最白話的方式解釋 Game Log 背後的構想。技術細節會隨研究進度補上來源與結論。

## 把它想成一條流水線

```
對戰影像  →  定時截圖  →  挑出關鍵畫面  →  判讀成文字事件  →  分回合分組  →  對戰紀錄
```

每一站都有它要解決的小問題：

### 1. 對戰影像（來源）
可能來自：擷取盒 + OBS 接出的 Switch 直播、錄好的影片、或正在看的直播。
**待研究的問題**：瀏覽器能不能穩定地「看到」這些來源？授權方式是什麼？

### 2. 定時截圖
每隔一小段時間抓一張畫面。
**待研究的問題**：間隔多寬最划算？太密會浪費運算，太疏會漏掉關鍵瞬間。

### 3. 挑出關鍵畫面
大多數截圖跟前一張幾乎一樣，沒有新資訊。我們用便宜的方法（比較前後畫面的差異、只看畫面中會變化的區域）先過濾掉「沒事發生」的截圖。
**直覺**：只在「畫面變了」的時候才花力氣去判讀。

### 4. 判讀成文字事件
這是最關鍵也最難的一站。把關鍵截圖變成像這樣的文字：
- `特性發動：威嚇`
- `招式：地震`
- `換人：A 換成 B`

**目前的主要假設**：畫面**底部的訊息框**會用文字描述正在發生的事，所以用 OCR（文字辨識）去讀它，可能是訊號最濃、最可靠的來源。這個假設要用原型驗證。

### 5. 分回合分組
把零散事件，依規則歸到「第幾回合、第幾階段」。例如：偵測到回合開始的畫面 → 開新回合；偵測到回合結算 → 收尾。
**這是一個狀態機**：根據事件的種類與順序，推斷比賽進行到哪裡了。

### 6. 對戰紀錄
最後輸出一份分回合的紀錄，給你復盤用。
