# Game Log 功能

Game Log 是這個產品要做的**第一個功能**。目標：把一場對戰影像，自動變成一份好讀的回合紀錄。

## 它要解決的問題

打完一場對戰，你想知道：
- 每一回合各方做了什麼？（出招、換人、保護…）
- 哪些特性在什麼時候發動了？（例如威嚇、不服輸）
- 局勢是怎麼一步步演變到結果的？

現在要回答這些，只能倒帶影片。我們想讓它**自動生成**。

## 它怎麼運作（白話版）

1. **拿到畫面**：你有一段對戰影像——可能是用擷取盒 + OBS 把 Switch 畫面接出來的直播，或是一段錄好的影片、或正在看的直播。
2. **授權給工具**：你授權這個 web app 去「看」這段畫面。
3. **定時擷取畫面**：工具每隔一小段時間（間隔會經過測試調整，例如約一秒）擷取一張截圖。
4. **挑出有用的截圖**：大部分截圖其實沒有新資訊。工具用一套規則，只留下「有事情發生」的那些——例如特性發動、有人出招、有人換上場、回合結束某些狀態消失。
5. **把截圖變成文字**：把這些關鍵截圖判讀成文字事件，例如「特性發動：威嚇」「特性發動：不服輸」。
6. **分組成回合與階段**：再用規則判斷每個事件屬於「第幾回合、第幾階段」，把零散事件組織成結構清楚的紀錄。
7. **交給你復盤**：最後產出一份分回合的對戰紀錄，讓你回頭檢討。

## 為什麼這件事不簡單（誠實說）

- **最難的不是截圖，是判讀。** 要可靠地看出「是哪隻發動了什麼特性、用了什麼招、誰換了人」並不容易。我們目前的假設是：畫面**底部的訊息框文字**很可能是最濃的線索（用文字辨識 OCR 去讀它）。這個假設需要實際做原型驗證。
- **畫質、語言、版面都會變。** 不同來源的畫面清晰度、遊戲語言、UI 版面都不同，會影響判讀準確度。

## 我們的策略：先把一條路走通

我們不會一開始就追求辨識所有特性與招式。MVP（最小可用版本）會先：
- 鎖定**單一、固定的畫面來源**；
- 先把**回合邊界**與**換人事件**這類最有價值、相對好辨識的訊號做穩；
- 把整條 pipeline（畫面 → 截圖 → 篩選 → 文字 → 分組 → 紀錄）跑通。

把一條窄但完整的路走通，遠比一次想做全部更有價值。
