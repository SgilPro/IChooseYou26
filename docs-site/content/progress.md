## 產品線：最重要的結論

> **做得到，但「全自動、零錯誤」做不到。** 建議走「**半自動 + 人工校正**」：機器先抓出關鍵畫面、辨識大部分文字事件，使用者再快速確認 / 修正。

各步驟可行性（紅綠燈）：

| 步驟 | 可行性 | 重點 |
|------|--------|------|
| 拿到畫面 | 🟢 | 最推薦 **OBS 虛擬攝影機**（瀏覽器當 webcam 讀）；本機影片檔也行。**YouTube 等第三方串流網址因防盜（CORS）走不通。** |
| 定時截圖 | 🟢 | 用 canvas 抓圖，每秒 1～2 張毫無壓力。 |
| 過濾關鍵畫面 | 🟢 / 🟡 | 用感知雜湊比對前後差異很快；難在「什麼算關鍵變化」的規則要靠真實畫面調。 |
| 辨識文字（OCR） | 🟡 | **最不確定、最該先打樣。** 底部訊息框文字是最濃訊號；建議比對固定字典校正。 |
| 結構化分回合 | 🟢 | 對戰流程確定性高，可用狀態機歸位。 |

**MVP 方向**：純前端為主（React + TypeScript + Vite、Web Worker、IndexedDB），輸入先吃**本地影片檔**，輸出是**可編輯的事件時間軸**。

## 領域線：最有價值的發現

- **Limitless VGC 有真正的公開 REST API**（賽事、名次、對戰配對），甚至支援 webhooks——可驅動事件式的學習更新。
- **Smogon 使用率**可透過 `data.pkmn.cc`（`@pkmn/smogon`）取得乾淨 JSON，每 24 小時更新。
- **`@smogon/calc`**（npm）是官方傷害公式，可直接當傷害 / 擊倒計算引擎。
- **pikalytics 與 Smogon 都沒有官方公開 API**（已查證），所以放在人工交叉比對。
- 影像辨識素材：PokeAPI / Pokémon HOME sprites；中文命名以**神奇寶貝百科**為準，需建立 EN/JA/zh-Hant 跨語言對照表。
- 學習方法：**雙軌貝氏交叉驗證**（人類直覺講「為什麼」 × 原始數據驗證），靠 cron 三層反思迴圈持續更新。
