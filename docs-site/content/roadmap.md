# 藍圖與方向

這頁說明我們打算怎麼一步步把這個產品做出來。**這是會變動的計畫**——研究與原型驗證會讓我們修正方向，而這正是我們想要的。

## 階段規劃

### 階段 0：研究與可行性（第一輪已完成）
- ✅ 釐清技術可行性：結論是「可行，但走半自動 + 人工校正」。
- ✅ 設計詳細使用者流程。
- ✅ 領域線盤點學習資源、資料來源 / API、影像辨識素材，訂出學習路徑。
- ⏳ **下一步**：做兩個原型（OCR 準確度、擷取 / 過濾 pipeline）決定 go/no-go。

### 階段 1：MVP（最小可用版本）
- 輸入先吃**本地影片檔**，把整條流水線跑通。
- 純前端為主（React + TypeScript + Vite、Web Worker、IndexedDB）。
- 截圖 → 關鍵影格過濾 → OCR 訊息框 → 產出**可編輯的事件時間軸**（含截圖縮圖）。
- 先做穩**回合邊界**與**換人**這類高價值、好辨識的事件。

### 階段 2：v1
- 加 **OBS 虛擬攝影機**即時擷取。
- 加寶可夢 / 招式 / 特性**字典比對**校正，自動分回合。
- 擴大可辨識事件，提升對不同畫質 / 語言 / 版面的耐受度。

### 階段 3：v2 與更多功能
- HP 條 / 狀態圖示視覺辨識、雲端 OCR、帳號雲端儲存、多語系、分享復盤連結。
- 接入 **Limitless VGC API**、**Smogon 使用率**、**`@smogon/calc`** 等資料源，往 pikalytics / serebii 那類完整對戰工具站擴張。

## 兩條並行的主線

我們同時推進兩件事，缺一不可：

1. **產品線**：把功能從研究 → 原型 → 可用的 web app。
2. **領域線**：真正學會雙打對戰知識。一個不懂對戰的工具，做不出對玩家有用的判讀規則。

## 我們會怎麼工作

- **小步前進，持續持久化**：每完成一段就保存（commit）。
- **先查證再下結論**：技術與對戰知識的宣稱都要有來源或實測。
- **公開、白話地寫文件**：就是你正在看的這份 live docs。
- **自動化推進**：Ditto 會用排程（cron）定期推進研究、反思、整理文件。
