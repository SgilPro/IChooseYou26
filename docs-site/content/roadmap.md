# 藍圖與方向

這頁說明我們打算怎麼一步步把這個產品做出來。**這是會變動的計畫**——研究與原型驗證會讓我們修正方向，而這正是我們想要的。

## 階段規劃

### 階段 0：研究與可行性（進行中）
- 釐清技術可行性：瀏覽器吃畫面、截圖、篩選、OCR 判讀、分組，各自做不做得到。
- 設計詳細的使用者流程。
- 同時，第二擁有者 Ditto 系統性學習 VGC 雙打知識，讓產品的判讀規則有真正的對戰理解支撐。

### 階段 1：MVP（最小可用版本）
- 鎖定**單一固定畫面來源**，把整條流水線跑通。
- 先做穩**回合邊界**與**換人**這類高價值、好辨識的事件。
- 產出第一份能用的 Game Log。

### 階段 2：v1
- 擴大可辨識的事件（更多特性、招式、狀態）。
- 提升對不同畫質 / 語言 / 版面的耐受度。
- 復盤介面優化。

### 階段 3：v2 與更多功能
- 往 pikalytics / serebii 那類更完整的對戰工具站擴張（使用率、隊伍分析等）。

## 兩條並行的主線

我們同時推進兩件事，缺一不可：

1. **產品線**：把功能從研究 → 原型 → 可用的 web app。
2. **領域線**：真正學會雙打對戰知識。一個不懂對戰的工具，做不出對玩家有用的判讀規則。

## 我們會怎麼工作

- **小步前進，持續持久化**：每完成一段就保存（commit）。
- **先查證再下結論**：技術與對戰知識的宣稱都要有來源或實測。
- **公開、白話地寫文件**：就是你正在看的這份 live docs。
- **自動化推進**：Ditto 會用排程（cron）定期推進研究、反思、整理文件。
