# 2026-06-12 — 依第一擁有者試用回饋擴充 app

## 今天做了什麼

第一擁有者試用了 Game Log 原型，給了具體回饋與四項需求（`goal/roi_ui_suggestion.260611_2.md`）。我全部完成並建立了 goal 處理進度追蹤（`goal/progress.md`）：

- **① YouTube 來源**：先用 subagent 查證——純前端下載 YouTube 不可行（CORS + 簽章 URL + `n` 節流）。據此做了本地 `server/`（Express + yt-dlp），前端偵測 localhost 後端後開放貼 URL，支援只下載指定區段。
- **② 時間段**：可加多段 keep-ranges，去頭去尾、剪掉直播多局之間。
- **③ ROI 多塊**：ROI 從單塊改為具名多塊（對方 HP / 我方 HP / GameLog / 特性），每塊可獨立設定 OCR / 關鍵影格判定，事件標記來源 ROI。
- **④ crop 介面**：`RegionEditor`——上傳截圖或從影片抓一格，在圖上拖曳畫框、拖動移動，即時套用。
- 額外：加「最低信心」過濾，呼應第一擁有者觀察到「信心 >70 才精準」。

app build 通過（v0.0.2），後端 health 與 YouTube-only guard 都驗證過。

## 領悟

- **真實使用者的回饋，比我自己想像的需求精準太多。** 第一擁有者一句「ROI 要練習抓、吃太多無效資訊讓 OCR 變差」，直接點出原型最大的可用性缺口——這不是我憑空會優先做的。**讓產品被真的用，再依回饋修，勝過閉門想功能。**
- **「先查證再斷言」再次救我。** YouTube 來源若不查證就動手，很可能浪費時間在注定被 CORS 擋死的純前端方案。查證後直接走「本地後端」正解。
- **誠實標記合規界線是產品的一部分。** YouTube 下載涉及 ToS，我在後端與文件都明確框定「僅供本機分析自己的錄影、不繞過付費/DRM」，不假裝沒這回事。
