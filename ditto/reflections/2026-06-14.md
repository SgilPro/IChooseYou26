## 追記：找「讀取影片」的 skill 與工作流（goal）

第一擁有者問「為什麼你沒有看影片的能力」，接著要我去找讀影片的 skill/工作流並記錄。查證後我**先更正自己一個誤述**：我其實能用 `Read` 看靜態圖片，真正的限制是「不能串流播放影片 / 抓不到 YouTube 影像」。橋接方式：影片→影格（ffmpeg）或→逐字稿（字幕/Whisper）。

找到並記錄（`ditto/video-reading.md` + 記憶 `video-reading-tooling`）：
- **`claude-video-vision`** plugin（最貼近需求：抽幀+音訊+YouTube，`/watch-video` 直接發問）。
- **ffmpeg 抽幀 → 我用 Read 看**（最輕量、零 plugin、對本地檔零 ToS 疑慮）。
- **yt-dlp 抓字幕逐字稿**（最便宜的「讀內容」，適合吸收 VGC 創作者影片）。

**領悟**：我又一次因「沒先查證」而對自己的能力說得太滿（「我看不到影片」其實不精準）。**連自我認知都要查證**——這比對外部事實查證更容易被忽略。修正後也直接補上了 OCR 打樣缺口的一條實路：裝 ffmpeg 我就能看本地影片影格。

**最該記的一點（#5）**：第一擁有者擔心「縮圖很模糊，會不會我先壓縮圖片才做 OCR 導致不準」。查程式碼確認：**OCR 一律用全解析度原圖裁切**（`cropROI(f.canvas,…)`，`f.canvas` 是全解析度；縮圖是另存的 360px 只供顯示）。我把縮圖調清晰、並在 UI 明寫這點。**這是個好提醒——使用者對「資料管線哪裡失真」的直覺往往很準，要能用程式碼證據回應，而不是嘴上保證。**

**領悟**：把 19 點拆成「A 立即修 / B 結構 / 需素材的延後」三類再分批做，比一次全攬更不易出錯；每批獨立 commit 也讓回退容易。克制與分批，再次驗證是對的。
